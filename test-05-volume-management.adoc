== Volume management

NetApp AFX makes some changes to how volumes are created and managed. This test aims to display some of those changes, show scale, and how volumes move automatically.

These provide a location for NVRAM commits to occur, since we still write the same way as unified ONTAP. By default, all volumes are created in the Storage Availability Zone and ONTAP handles the volume placement. +
View the volume count for each data aggregate after creating the FlexGroup volume. Note that the volumes counts are imbalanced. +

Create a new FlexGroup volume without specifying the aggregate name and check the volume count again. Note how ONTAP is attempting to balance the placement across by placing new volumes evenly across nodes, but the imbalance is still present on the manually placed volumes. +
AFX::*> volume create -volume fg2 -auto-provision-as flexgroup +
 +
rtp-afx1k-c01::*> aggr show -aggregate data* -fields volcount +
aggregate      volcount +
-------------- -------- +
dataFA_2_p0_i1 41 +
dataFA_4_p0_i1 20 +
 +
The imbalance is present because when you manually override ONTAP volume placement, it disables the rebalance functionality (-atm-state). Check that in diag priv. +
rtp-afx1k-c01::*> vol show -vserver svm1 -volume fg1,fg2 -fields atm-state +
vserver volume atm-state +
------- ------ --------- +
svm1    fg1    disabled +
svm1    fg2    enabled +
 +
That can be re-enabled. Use the following command. +
rtp-afx1k-c01::*> set diag; vol modify -volume fg1 -atm-state enabled +
 +
After ~5 minutes, ONTAP runs a job that periodically rebalances the volume counts to even things out. You can either wait for that duration or manually start this process.  +
 +
After ~5 minutes, we see this: +
rtp-afx1k-c01::*> aggr show -aggregate data* -fields volcount,node +
aggregate      node             volcount +
-------------- ---------------- -------- +
dataFA_2_p0_i1 rtp-afx1k-c01-01 31 +
dataFA_4_p0_i1 rtp-afx1k-c01-02 30 +
To manually start the rebalance, a diag level command is used (and is not recommended to use on production workloads unless guided by NetApp support). +
AFX::> set diag +
AFX::*> debug smdb table atm_kick run +
 +
HA failover testing in a later part of this test plan will cover volume rebalancing there as well. +
