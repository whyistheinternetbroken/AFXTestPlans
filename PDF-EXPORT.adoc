= PDF export for customer sharing
:toc: left
:toclevels: 2
:icons: font

This note covers building a single PDF from the AsciiDoc sources for **request-basis** sharing (NetApp account teams / potential customers). Keep the GitHub repo private; share the PDF through Box, OneDrive, or SharePoint with view-only access and an expiration when possible.

== Prerequisites

Pick one:

* **Ruby gems (local):** Ruby 3.x, then `gem install asciidoctor-pdf rouge`
* **Docker:** Docker Desktop with pull access to `asciidoctor/docker-asciidoctor`

Images resolve from `TestPlan/images/` via the included pages. Build from the **repository root**.

== Export

Windows (PowerShell):

[source,powershell]
----
.\scripts\export-pdf.ps1
----

Linux / macOS:

[source,shell]
----
./scripts/export-pdf.sh
----

Default output:

`exports/AFX-Test-Plan-ONTAP-9.19.1.pdf`

Optional arguments (PowerShell):

[source,powershell]
----
.\scripts\export-pdf.ps1 -OutDir exports -OutFile AFX-Test-Plan-customer.pdf
----

The master include file is xref:book.adoc[`book.adoc`]. Do not hand-edit customer PDFs from individual `TestPlan/*.adoc` pages unless you intentionally want a subset.

== Sharing guidance

* Upload the PDF to Box / OneDrive / SharePoint (not a public gist or public Pages site).
* Use **view-only** permissions and set an **expiration** (or remove access after the engagement).
* Prefer password-protected or authenticated shares for customer recipients.
* NetApp internal reviewers can continue using the private GitHub repo; use PDF for external request-basis access.

== Notes

* Navigation “Previous / Next” tables and some inter-page `xref:` links are oriented to the multi-file HTML/GitHub layout. In PDF they may appear as ordinary links or text; content is still included.
* `exports/` is gitignored so generated PDFs are not committed by default.
* Re-run the export after content updates before sending a new customer copy.
