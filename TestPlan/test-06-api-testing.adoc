== API testing/seamless support for customer automation

NetApp AFX is intended to provide a seamless ONTAP experience. Included in that is API parity between unified and NetApp AFX so that legacy automation suites using REST API calls to ONTAP will be plug-and-play into NetApp AFX.
If no current API-based automation suites are in use, then some basic REST API calls are provided to test functionality. See xref:appendix-rest-api.adoc[REST API Examples] for examples.

For the expected personality-specific REST API gaps (SAN, MetroCluster, aggregates, and AFX-only storage availability zone endpoints), see xref:appendix-rest-api-personality-differences.adoc[REST API personality differences].

[cols="<1",width="100%"]
|===
a| *Test procedure:*

. Test your REST API calls against unified ONTAP.

. If you are not already using standard automation REST calls against unified ONTAP, then leverage the example calls in xref:appendix-rest-api.adoc[REST API Examples].

. Test your REST API calls against NetApp AFX. If you are not already using standard automation REST calls against NetApp AFX, then leverage the example calls in xref:appendix-rest-api.adoc[REST API Examples].

a| *Expected outcome(s):*

* REST API calls used with unified ONTAP are tested.
* The same REST API calls are tested against NetApp AFX and are successful, except for personality-specific gaps listed in xref:appendix-rest-api-personality-differences.adoc[REST API personality differences] (SAN, NVMe, Fibre Channel, MetroCluster, aggregates, LUNs, namespaces, and AFX-only storage availability zone endpoints).
|===
