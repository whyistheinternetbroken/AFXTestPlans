SPECstorage Solution 2020 (commonly called SPEC SFS 2020) EDA workload profiles: frontend, backend, and blended terminology; NFS operation distributions; and operation definitions.


[[about-eda-frontend-backend-and-blended-terminology]]
== About EDA frontend, backend, and blended terminology

The EDA terms used in this document for workloads (frontend, backend, blended) refer to the workloads documented in SPECstorage Solution 2020. Specifically:

* *Frontend* — large number of small files, higher metadata
* *Backend* — lower number of large files, 50/50 read/write (sequential)
* *Blended* — a mix of both frontend and backend workloads

See https://www.spec.org/storage2020/ for details.


[[spec-sfs-2020]]
== SPEC SFS 2020

We will be using the SPECstorage Solution 2020 benchmark to simulate EDA frontend, backend, and blended workloads. The test profiles use the workload profiles found in the link:https://www.spec.org/storage2020/[SPECstorage Solution 2020] documentation, as well as details on how to set up and configure the benchmark.

The official EDA workload is a blend of two component workloads:

* *EDA_FRONTEND* — metadata-intensive; many small files (frontend design flow).
* *EDA_BACKEND* — sequential read/write intensive; larger assembly files (backend design flow).

In the blended workload, the process ratio is maintained at 3 frontend processes for every 2 backend processes as load increases.

*Note:* Due to the metadata-heavy nature of frontend EDA workloads, it is recommended to use NFSv3. See xref:appendix-nfs-considerations.adoc[NFS Considerations].

[[definition-of-relevant-operations-in-spec-sfs-2020]]
=== Definition of relevant operations in SPEC SFS 2020

The following section defines the operations mentioned in <<frontend-eda-workload-breakdown----specsfs-2020>> and <<backend-eda-workload-breakdown>>.

[cols="1,1",options="header"]
|===
| Operation type | What it does
| read | Sequential reads to an already open file.
| read file | Open, read, close file. End-to-end read.
| mmap read | Memory map read.
| random read | Random read (SPEC: rand read).
| write | Sequential write to an already open file.
| write file | Open, write, close. End-to-end write.
| mmap write | Memory map write.
| random write | Random write (SPEC: rand write).
| rmw | Read/modify/write.
| append | Add data to end of existing file.
| mkdir | Make directory.
| rmdir | Remove directory.
| readdir | List contents of directory. (Includes readdir+ operations)
| create | Create file metadata operation; checks if file exists, allocates a new inode.
| unlink | Deletes a file.
| unlink2 | 2nd unlink on a different file.
| stat | Retrieves the attributes of a file or directory, such as size, permissions, owner, and timestamps. (ie, du and ls)
| access | Checks the access permissions for a file or directory to determine if the client has the necessary permissions (read, write, execute).
| rename | Rename a file or folder.
| copyfile | Copies a file from one to another.
| lock | Locks a file (SPEC: locking).
| chmod | Change the permissions of a file or folder.
| statfs | Retrieve information about the overall file system. (ie, df)
| pathconf | Retrieves configuration information about a file or directory, such as maximum filename length, maximum path length, and other file system limits.
|===
