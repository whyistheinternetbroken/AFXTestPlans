== Executive Summary

This test plan validates NFS storage performance using NFSv4.1 with parallel NFS (pNFS) and session trunking, targeting *12+ GB/s aggregate throughput* with *5:1 deduplication-friendly datasets*. The plan assumes modern all-flash or hybrid storage arrays with NFS capabilities.

== Client Sizing & Requirements

=== Throughput Budget per Client

[cols="2,3"]
|===
| Parameter | Value

| Target aggregate throughput
| 12 GB/s (96 Gb/s)

| Per-client realistic NFS throughput
| ~1.5–2 GB/s (with 25GbE dual-port or 100GbE)

| *Minimum clients required*
| *8 clients*

| *Recommended clients*
| *10–12 clients* (headroom + consistency)
|===

=== Mount Options for NFSv4.1 + pNFS + Session Trunking

.Primary mount with pNFS file layout
[source,bash]
----
mount -t nfs4 -o \
  vers=4.1,\
  proto=tcp,\
  rsize=262144,\
  wsize=262144,\
  hard,\
  intr,\
  trunkdiscovery,\
  sec=sys,\
  actimeo=0,\
  noac,\
  nordirplus \
  <storage_ip>:/export/vdbench_test /mnt/vdbench
----

*Note:* Use either `nconnect` or session trunking (`trunkdiscovery`) with these options, but not both due to some unpredictable client behavior when combining them with pNFS.

.Multi-path trunking (Linux kernel 6.3+ with trunkdiscovery)
[source,bash]
----
mount -t nfs4 -o vers=4.1,trunkdiscovery,proto=tcp,rsize=262144,wsize=262144 \
  storage-ip1:/export/vdbench_test /mnt/vdbench

# Optional: mount an additional path explicitly if your environment requires it:
mount -t nfs4 -o vers=4.1,trunkdiscovery,proto=tcp,rsize=262144,wsize=262144 \
  storage-ip2:/export/vdbench_test /mnt/vdbench2
----

== Deduplication-Friendly Dataset Design (5:1 Ratio)

=== Strategy

To achieve a *5:1 dedupe ratio*, 80% of the data blocks must be duplicates and 20% unique. VDBench achieves this through the `dedupratio` and `dedupunit` parameters.

=== Dedupe Parameters

[cols="2,1,4"]
|===
| Parameter | Value | Purpose

| `dedupratio=5`
| 5:1
| 80% duplicate blocks, 20% unique

| `dedupunit=4k`
| 4 KB
| Dedup granularity matching storage inline dedupe block size

| `dedupflipflop=yes`
| Enabled
| Ensures re-writes maintain dedupe pattern

| `dedupsets=5`
| 5 sets
| Distributes dedupe patterns across multiple sets

| `compressratio=2`
| 2:1
| Additional compression on unique blocks
|===

=== Effective Storage Efficiency

[source,text]
----
Logical data written:  100 TB (across all clients)
After 5:1 dedupe:       20 TB
After 2:1 compression:  10 TB  (physical)
Overall efficiency:     10:1
----

== Test Execution Procedures

=== Pre-Test Checklist

.pre_test_checks.sh — Run on each client
[source,bash]
----
#!/bin/bash

echo "=== NFS Mount Verification ==="
mount | grep nfs4
nfsstat -m

echo "=== pNFS Layout Verification ==="
cat /proc/fs/nfsfs/volumes
grep -r pnfs /proc/fs/nfsfs/ 2>/dev/null

echo "=== Session Trunking Verification ==="
# Check number of TCP connections to storage
ss -tn | grep <storage_ip> | wc -l

echo "=== Network Configuration ==="
ip link show | grep -E "mtu|state UP"
ethtool <nic_name> | grep Speed

echo "=== Jumbo Frame Test ==="
ping -M do -s 8972 <storage_ip> -c 3

echo "=== VDBench Version ==="
/opt/vdbench/vdbench -t 2>&1 | head -5

echo "=== NFS Kernel Parameters ==="
cat /proc/sys/sunrpc/tcp_slot_table_entries
cat /proc/sys/sunrpc/tcp_max_slot_table_entries

echo "=== CPU & Memory ==="
lscpu | grep -E "^CPU$s$|Model name|Thread"
free -h
----

=== Trunking Remount Script

.remount_trunking.sh
[source,bash]
----
#!/bin/bash
# Usage: ./remount_trunking.sh 16  OR  ./remount_trunking.sh 1

NCONN=${1:-16}
STORAGE_IP="10.0.1.100"
EXPORT="/export/vdbench_test"
MOUNTPOINT="/mnt/vdbench"

umount -f $MOUNTPOINT 2>/dev/null
sleep 2

mount -t nfs4 -o \
  vers=4.1,\
  proto=tcp,\
  rsize=262144,\
  wsize=262144,\
  hard,\
  nconnect=${NCONN},\
  sec=sys \
  ${STORAGE_IP}:${EXPORT} ${MOUNTPOINT}

echo "Mounted with nconnect=${NCONN}"
ss -tn | grep ${STORAGE_IP} | wc -l
echo "TCP connections established"
----

=== Client-Side Monitoring Script

.client_monitor.sh — Run in background during tests
[source,bash]
----
#!/bin/bash
OUTPUT_DIR="/results/client_stats"
mkdir -p $OUTPUT_DIR
INTERVAL=5

while true; do
    TIMESTAMP=$(date +%Y%m%d_%H%M%S)

    # Network throughput
    sar -n DEV $INTERVAL 1 >> ${OUTPUT_DIR}/network_${HOSTNAME}.log

    # CPU utilization
    sar -u $INTERVAL 1 >> ${OUTPUT_DIR}/cpu_${HOSTNAME}.log

    # NFS statistics
    nfsstat -c >> ${OUTPUT_DIR}/nfsstat_${HOSTNAME}.log

    # NFS I/O stats
    nfsiostat $INTERVAL 1 >> ${OUTPUT_DIR}/nfsiostat_${HOSTNAME}.log

    # TCP connection count (trunking verification)
    echo "${TIMESTAMP} $(ss -tn | grep -c ':2049')" >> ${OUTPUT_DIR}/tcp_conns_${HOSTNAME}.log
done
----

== Results Analysis Template

=== VDBench Output Parsing

.parse_results.sh
[source,bash]
----
#!/bin/bash
OUTDIR=$1

echo "=== Aggregate Throughput Summary ==="
grep "avg_2" ${OUTDIR}/totals.html | awk '{print "Read MB/s:", $X, "Write MB/s:", $Y}'

# Extract key metrics from flatfile.html
echo "=== Per-Interval Throughput ==="
grep -v "^$\|Starting\|Vdbench" ${OUTDIR}/flatfile.html | \
  awk -F',' '{printf "Time: %s | Read MB/s: %s | Write MB/s: %s | IOPS: %s | Lat: %s ms\n", $1, $NF-3, $NF-2, $NF-1, $NF}'
----

== Troubleshooting Guide

[cols="2,3,4"]
|===
| Issue | Diagnosis | Resolution

| Throughput < 1 GB/s per client
| Check `nconnect` value, NIC speed
| Verify mount options, check `ss -tn` for connection count

| pNFS not active
| `nfsstat -m` shows no pNFS
| Verify storage supports pNFS file layouts, check `/proc/fs/nfsfs/volumes`

| High latency spikes
| Storage dedupe overhead
| Check storage CPU, consider async dedupe

| Dedupe ratio < 4:1
| VDBench dedupe params incorrect
| Verify `dedupratio=5,dedupunit=4096` in all SD definitions

| TCP retransmits
| Network congestion/drops
| Check switch buffer utilization, verify flow control (PFC/ECN)

| Uneven client throughput
| pNFS layout imbalance
| Check data server distribution, rebalance volumes

| `nconnect` ignored
| Kernel too old
| Requires Linux kernel ≥ 5.3 for `nconnect`, ≥ 6.3 for `trunkdiscovery`
|===

== Quick-Start Single-File Config

For a simplified single-file test (useful for initial validation):

.quick_test.vdb
[source,ini]
----
# quick_test.vdb — Single client quick validation
# Run: /opt/vdbench/vdbench -f quick_test.vdb -o /results/quick

hd=default,vdbench=/opt/vdbench,user=root,shell=ssh
hd=hd1,system=localhost

sd=sd1,hd=hd1,lun=/mnt/vdbench/quicktest/file1,size=500g,threads=32,\
   dedupratio=5,dedupunit=4096,dedupsets=5,compressratio=2,openflags=o_direct

wd=wd_seqr,sd=sd*,rdpct=100,xfersize=1m,seekpct=sequential
wd=wd_seqw,sd=sd*,rdpct=0,xfersize=1m,seekpct=sequential
wd=wd_randr,sd=sd*,rdpct=100,xfersize=4k,seekpct=random

rd=rd_prefill,wd=wd_seqw,iorate=max,elapsed=3600,interval=10,warmup=0
rd=rd_seqread,wd=wd_seqr,iorate=max,elapsed=300,interval=10,warmup=30
rd=rd_seqwrite,wd=wd_seqw,iorate=max,elapsed=300,interval=10,warmup=30
rd=rd_randread,wd=wd_randr,iorate=max,elapsed=300,interval=10,warmup=30
----
