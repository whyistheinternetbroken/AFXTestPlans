[[glossary-of-nfs-operation-types-found-in-ontap-statistics]]
=== Glossary of NFS operation types found in ONTAP statistics

The following table defines the NFS operation types seen in ONTAP performance statistics and classifies them by metadata or IO.

[cols="1,1,1"]
|===
| Operation | Use case | Category
| ACCESS | Permission checks/verifcation of files/directory. | Metadata
| CLOSE | Call to close an open file. Buffered data written, locks are released. | Metadata
| COMPOUND | Multiple calls combine into a single call. Can include any of the other operation calls mentioned here. | Metadata
| CREATE | Create a new file. | Metadata
| GETATTR | Get file attributes, including permissions, atime, size, etc. (find, ls) | Metadata
| GETDEVICEINFO | pNFS call to get device information from the NFS server.  +
(interface to volume relationship) | Metadata
| GETFH | Retrieves the file handle for the file or directory. | Metadata
| LAYOUTGET | pNFS call to get layout information from NFS server. | Metadata
| LOOKUP | Resolve a file or directory name to its file handle. | Metadata
| OPEN | Opens the file using the filehandle gathered in LOOKUP | Metadata
| PUTFH | Sets filehandle during mount of an NFS export. | Metadata
| READ | Reads a file. Can be random or sequential. | IO
| READDIR | Reads contents of a directory; lists files and directory names with attributes. | Metadata
| READDIRPLUS | Enhanced version of READDIR; used to reduce GETATTR and LOOKUP | Metadata
| SEQUENCE | NFSv4.1 and later; manages state of client->server session for proper request ordering and session recovery. | Metadata
| SETATTR | Modifies attributes for a file or directory. | Metadata
| WRITE | Writes a file. Can be random or sequential. | IO
|===

[[pnfs-counters----nfsv4_1_diag-diag-priv]]
=== pNFS counters -- nfsv4_1_diag (diag priv)

*Object: `nfsv4_1_diag`*
[cols="2,3",options="header"]
|===
| Counter | Description

| `cachedio_delete_byttl_pnfs_ds`
| Number of times the Nfsv41CachedIO pNFS DS object is deleted due to ttl.

| `cachedio_fh_pnfs`
| Number of times the Nfsv41CachedIO operation was invoked on a clustered Data ONTAP filehandle containing pNFS Device information but no Qtree export information.

| `cachedio_fh_pnfs_qtree`
| Number of times the Nfsv41CachedIO operation was invoked on a clustered Data ONTAP filehandle containing pNFS Device and Qtree export information.

| `cb_layoutrecall_rcv_error`
| The number of NFSv4.1 CB_LAYOUTRECALL received with error. The CB_LAYOUTRECALL operation is used by the server to recall layouts from the client.

| `cb_layoutrecall_rcv_success`
| The number of NFSv4.1 CB_LAYOUTRECALL received successfully. The CB_LAYOUTRECALL operation is used by the server to recall layouts from the client.

| `cb_layoutrecall_send_error`
| The number of NFSv4.1 CB_LAYOUTRECALL sent with error. The CB_LAYOUTRECALL operation is used by the server to recall layouts from the client.

| `cb_layoutrecall_send_success`
| The number of NFSv4.1 CB_LAYOUTRECALL sent successfully. The CB_LAYOUTRECALL operation is used by the server to recall layouts from the client.

| `cb_notifydeviceid_rcv_error`
| The number of NFSv4.1 CB_NOTIFY_DEVICEID received with error. The CB_NOTIFY_DEVICEID operation is used by the server to send notifications to clients about changes to pNFS device IDs.

| `cb_notifydeviceid_rcv_success`

[[pnfs-statistics-example]]
==== pNFS statistics example

When you see "layoutget_total" incrementing, that means pNFS is sending and receiving device layouts to connected clients.

[%nowrap]
[source,console]
----
rtp-a70-c01::*> set advanced -confirmations off; statistics show -object nfsv4_1 -counter *layout* -sample-id sample_1393185

Object: nfsv4_1
Instance: AIML
Start-time: 5/15/2025 16:11:23
End-time: 5/15/2025 18:03:06
Elapsed-time: 6702s
Scope: rtp-a70-c01
Number of Constituents: 2 (complete_aggregation)
Counter                                                     Value
-------------------------------- --------------------------------
layoutget_avg_latency                                         8us
layoutget_success                                             216
layoutget_total                                               216
----
